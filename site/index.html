Engenharia e fabricação

Análise técnica de desenhos

Envie desenhos em PDF/imagem e, opcionalmente, as condicionais do cliente. A regra aplicada ficará limitada ao cliente e projeto desta execução.

🔒 PDFs e condicionais permanecem no armazenamento privado temporário
1

ZIP de desenhos

O ZIP pode conter apenas os PDFs ou também uma pasta com condicionais do cliente.

Somente desenhosTodos os PDFs e imagens serão tratados como desenhos. O perfil do cliente poderá ser reconhecido automaticamente.
Desenhos + condicionaisUse nomes ou pasta como “Condicionais”, “Specifications”, “Normas” ou “Requirements”.
Perfil cadastradoSelecione uma base permanente já validada para o cliente/projeto. Ela nunca será usada em outro cliente.
2

Separação desenhos × condicionais

Esta é uma prévia local; o servidor também lê o conteúdo das páginas para confirmar a função de cada arquivo.

3

Cliente e contexto

Esses dados determinam quais condicionais podem ser aplicadas.

4

Isolamento das condicionais

A base é resolvida em Cliente → Projeto → Área → Classe → Componente → Nota.

Regra obrigatória: uma condicional de SBM, PERENCO, Yinson ou qualquer outro cliente não será reaproveitada em outro cliente. Condicionais enviadas no ZIP valem somente para esta execução.

Arquitetura

Como a auditoria funciona

O GitHub Pages recebe o pacote, o Supabase mantém a fila privada e o GitHub Actions executa o n8n ou o motor visual especializado com GitHub Models.

01ZIP únicoUpload temporário e privado.
→
02Fila SupabaseTipo da análise e rastreabilidade.
→
03RoteamentoProposta via n8n ou desenho via visão.
→
04Conhecimento por clientePerfil isolado + condicionais temporárias.
→
05EntregáveisPDF, XLSX, JSON e DOCX quando aplicável.
Regra de segurança: preço, prazo, obrigação ou erro técnico sem evidência suficiente são marcados para validação humana. Condicionais não são compartilhadas entre clientes.
